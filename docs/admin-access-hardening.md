# แนวทาง: ล็อกสิทธิ์ดู/จัดการบัญชีผู้ใช้ให้แน่นขึ้น

> **สถานะ: ยังไม่ทำ — เก็บไว้เป็นแผน** (ตัดสินใจเลื่อนออกไปก่อน เพราะตอนนี้ยังไม่จำเป็น
> และจะทำให้ flow วุ่นวายเกินไป) เอกสารนี้เก็บเหตุผล + วิธีทำ ไว้ให้หยิบมาทำต่อได้ทันที

เป้าหมายที่คุยกันไว้: อยากล็อกว่า **ต้องเป็น admin คนนี้เท่านั้น (และยืนยันรหัสผ่าน)**
ถึงจะดูรายชื่อบัญชีผู้ใช้ทั้งหมดได้

---

## 1. ตอนนี้ระบบเป็นยังไงแล้ว

> **`aeris_auth.py` merge เข้า `server.py` บน Pi เรียบร้อยแล้ว (28 ก.ค. 69)**
> ระบบ login/สมัคร/อนุมัติกำลังทำงานจริง ไม่ใช่ mock — แอปตั้ง `useMockAuth: false`
> และผู้ใช้ถูกเก็บถาวรใน `users` table ใน `aeris_data.db`
> แปลว่าหัวข้อ "ทางเลือก" ด้านล่างนี้หยิบมาทำได้ทันทีเมื่อพร้อม

สิ่งที่ **มีอยู่แล้ว** (ไม่ต้องทำซ้ำ):

- `/api/admin/*` ทุกเส้นต้องมี `Authorization: Bearer <JWT>`
- [`require_admin`](../server/aeris_auth.py) **re-check role จาก DB ทุก request** — admin ที่ถูกลดสิทธิ์
  จะหมดสิทธิ์ทันที ไม่ต้องรอ token หมดอายุ
- ฝั่งแอป token เก็บใน main process (เข้ารหัส safeStorage) renderer ไม่เคยเห็น token
- `requireAdminToken()` ใน [`src/main/ipc.ts`](../src/main/ipc.ts) กันอีกชั้นก่อนยิงออก

สิ่งที่ **ยังเป็นช่องว่าง**:

| ช่องว่าง | ผลกระทบ |
|---|---|
| admin **ทุกคน** ดู/จัดการผู้ใช้ได้ | คนที่ถูก `promote` ทีหลังมีสิทธิ์เท่าเจ้าของ |
| token อายุ **30 วัน** | ถ้า token หลุด = เข้าถึง admin ได้ยาว 30 วัน |
| ไม่มีการถามรหัสผ่านซ้ำ | ใครมาเปิดแอปที่ค้างล็อกอินไว้ ก็กดดูรายชื่อได้เลย |

## 2. กฎเหล็กข้อเดียวที่ห้ามลืม

> **การบังคับสิทธิ์ต้องอยู่ที่ `server.py` เท่านั้น**

การซ่อนการ์ด "จัดการผู้ใช้" ใน Settings เป็นแค่ UX ไม่ใช่ security — ใครก็ทำแบบนี้ได้:

```bash
curl -H "Authorization: Bearer <token>" http://<pi>:8000/api/admin/users
```

และ **ห้ามเอา username/password/secret ไปไว้ใน `src/main/config.ts`** เพราะโค้ด Electron
ถูกแพ็กไปกับ `.exe` / `.AppImage` — แตกไฟล์ออกมาอ่านได้หมด ของลับอยู่บน Pi เท่านั้น

## 3. ทางเลือก 3 ระดับ

### ระดับ 1 — ล็อกเป็น "เจ้าของ" (owner) คนเดียว

แยก "admin ทั่วไป" ออกจาก "เจ้าของระบบ"

```sql
ALTER TABLE users ADD COLUMN is_owner INTEGER NOT NULL DEFAULT 0;
-- backfill DB เดิม: ให้ user คนแรกเป็นเจ้าของ
UPDATE users SET is_owner = 1 WHERE id = (SELECT MIN(id) FROM users);
```

- ตอน `signup` ถ้าเป็นคนแรก → `role='admin'` **และ** `is_owner=1`
- เพิ่ม dependency `require_owner` (ก๊อปจาก `require_admin` แล้วเช็ค `is_owner=1` เพิ่ม)
- เอาไปใส่เฉพาะเส้นที่อ่อนไหว: `GET /api/admin/users`, `promote`, `reject`
  (จะปล่อย `approve` ให้ admin ทั่วไปทำได้ก็ได้ — แล้วแต่นโยบาย)

✅ ง่ายสุด แก้ไม่กี่บรรทัด ได้ผลทันที
⚠️ ต้องมี migration สำหรับ DB ที่มีข้อมูลแล้ว

### ระดับ 2 — ปักชื่อผู้ใช้ที่อนุญาตผ่าน env

```bash
export AERIS_OWNER_USERNAME=sittx
```

endpoint เทียบ `username` ใน JWT กับค่านี้

✅ ไม่ต้องแก้ schema เปลี่ยนเจ้าของง่าย
⚠️ ผูกกับ "ชื่อ" ถ้าเปลี่ยนชื่อผู้ใช้ต้องไปแก้ env ตาม

### ระดับ 3 — ขอรหัสผ่านซ้ำก่อนดู (step-up / "sudo mode") ⭐

ตรงกับโจทย์ที่สุด — แบบเดียวกับ GitHub ที่ถามรหัสซ้ำก่อนทำอะไรสำคัญ

**Server:**
- เพิ่ม `POST /api/auth/elevate` รับ `{ password }` → ตรวจ bcrypt ของ user ที่ถือ token นั้น
- ผ่านแล้วคืน **token อายุสั้น 5–10 นาที** ที่มี claim พิเศษ เช่น `scope: "admin_elevated"`
- `GET /api/admin/users` (และเส้นอ่อนไหวอื่น) ต้องมี scope นี้ ไม่งั้น **403**

**App:**
- ก่อนเปิดรายชื่อผู้ใช้ → เด้ง modal ให้กรอกรหัสผ่าน
- เก็บ elevated token ไว้ **ใน memory ของ main process เท่านั้น** (อย่าลง safeStorage)
  → ปิดแอปแล้วหายทันที ต้องยืนยันใหม่
- หมดอายุแล้วให้ถามซ้ำ

✅ กันเคส "แอปค้างล็อกอินทิ้งไว้" และ "token 30 วันหลุด" ได้จริง
⚠️ เพิ่มขั้นตอนให้ผู้ใช้ (แต่แค่ตอนเข้าส่วน admin เท่านั้น)

---

## 4. คำแนะนำ

**ทำ ระดับ 1 + ระดับ 3** = ได้ตรงโจทย์เป๊ะ *"ต้องเป็น admin คนนี้ และต้องพิมพ์รหัสผ่าน"*

ถ้าอยากเริ่มเบา ๆ → **ระดับ 1 อย่างเดียว** คุ้มที่สุดต่อความพยายาม

ของแถมที่ควรทำคู่กับระดับ 3:
- **จำกัดจำนวนครั้งที่กรอกรหัสผิด** (เช่น ผิด 5 ครั้ง ล็อก 15 นาที) กัน brute-force
- **audit log** บันทึกว่าใคร approve/promote/reject ใคร เมื่อไหร่

---

## 5. สิ่งที่ล็อกแบบนี้ *ไม่* ช่วย (ต้องรู้ไว้)

- ใครที่เข้าถึงตัว Pi หรือไฟล์ `aeris_data.db` ได้ → แก้ role ตัวเองเป็น admin ได้เลย ไม่ผ่าน API
- ตอนนี้ยังเป็น **HTTP ธรรมดา** ในวง LAN → รหัสผ่าน/token วิ่งแบบไม่เข้ารหัส
  คนที่ดักในวงเดียวกันอ่านได้ (ถ้าอยากแน่นจริงต้องมี HTTPS / reverse proxy)
- ถ้า `AERIS_JWT_SECRET` หลุด → ปลอม token ได้ทั้งระบบ
